# CLAUDE.md — mobile-app

Expo SDK 58 / React Native app for the DentalFlow API (`../backend`). It mirrors the web app (`../web-app`): same rules, same feature names. Read `AGENTS.md` too (Expo docs rule, commands).

## Stack
Expo Router · Uniwind (Tailwind 4) · React Native Reusables (shadcn for RN, in `src/components/ui`) · TanStack Query / Form · Zustand · Zod 4 · axios · socket.io-client · expo-secure-store.

## Structure
```
src/
├── app/              # Expo Router routes ONLY — zero logic. (auth)/ · (app)/ · select-location.tsx
│                     # _layout.tsx = providers + route guards (Stack.Protected)
├── features/<name>/  # ALL business logic: pages/ components/ hooks/ api/ schemas/ types/ + index.ts barrel
│                     # cross-feature imports go through the barrel
├── components/
│   ├── ui/           # RNR components — generated by the CLI, don't hand-edit
│   ├── forms/        # FieldWrapper, FormInput, fieldError
│   └── feedback/     # LoadingSkeleton, EmptyState, NoResultsState, ErrorState
├── lib/              # api, env, query-client, secure-storage, datetime, currency, utils
├── store/            # Zustand (useAuthStore: memory only)
├── providers/        # AppProviders
└── types/            # ApiResponse, Paginated
```

## Rules (same as web unless noted)
- Forms: `@tanstack/react-form` + Zod schema wired as `validators`; `useForm` in `hooks/use<Feature>Form.ts`; errors via `fieldError(field)`; submit disabled on `!canSubmit || isSubmitting`. NEVER react-hook-form.
- Every API call lives in `api/<feature>.api.ts` (uses `api` from `@/lib/api`), consumed by TanStack Query hooks. Responses are `ApiResponse<T>` → unwrap `res.data.data`.
- Every list/detail has loading (`LoadingSkeleton`), empty (`EmptyState`), error (`ErrorState` + retry) and filtered-empty (`NoResultsState`) states.
- Dates: only through `@/lib/datetime` (clinic timezone, never the phone's). Money: `@/lib/currency`.
- Access: `useAccess().can('perm')`, never role names. Permission keys come from `features/access/generated/catalog.ts` — regenerated by `npm run access:export` in `backend/` (writes web + mobile).
- Colours: theme tokens only (`bg-primary`, `text-muted-foreground`, `border-border`), no hex. No inline `style` for things a class can do. Safe-area: `pt-safe` / `pb-safe` / `py-safe`.
- Destructive actions go through `AlertDialog` confirm. Every icon-only button needs an accessibility label.
- Lists: `@shopify/flash-list` for anything long. Web's "forms in a Sheet" becomes a bottom sheet / modal screen here.

## Auth (differs from web)
No cookies. Login/refresh send `x-client-type: mobile`; the API then returns `refreshToken` (`sessionId:token`) in the body. It is kept ONLY in SecureStore (`lib/secure-storage`) and sent back as `x-refresh-token`. The access token is memory-only. `refreshSession()` is single-flight (the server rotates the token each call). Start-up restore = `useRestoreSession`; offline at start = `unreachable` (keep the session, offer retry), a rejected token = signed out. Backend side: `backend/src/auth/native-client.ts` (only honoured when the request has NO `Origin` header).

## Config
`EXPO_PUBLIC_API_URL` (see `.env.example`) — optional in dev, required for release builds.
