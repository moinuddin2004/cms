# Progress board

> Status values: `blocked` (dependency or decision missing) · `spec` (card not expanded yet — architect) ·
> `ready` (implementer may start) · `in-progress` · `review` (handoff written) · `changes-requested` · `done`.
> Implementers change only their own row (`in-progress`, `review`). The architect sets `ready`,
> `changes-requested`, `done`.

**Current phase:** 1 — Staff space · **Next up:** M1-03 (realtime), M1-06 (offline cache), M2-02b (patient Google), M2-03 (links — card to be expanded) · then M1-07 → M1-08 doctor queue · **Device:** M0-D open (must pass before Gate A) · **DB:** run M2-01 change file + M2-02 int spec on a disposable Postgres · Updated 2026-11-12

> **Parallel work rule:** one checkout = one implementer at a time. Two implementers in the same folder
> share one branch and one working tree (that is how M0-08 ended up on M0-01's branch). For parallel work
> each implementer needs its own `git worktree` (e.g. `git worktree add ../cms-be mobile/M0-09-...`).
> **Fresh worktree:** run `npm install` in `mobile-app/` (or `backend/`), and copy `mobile-app/expo-env.d.ts`
> from the main checkout (gitignored, generated by Expo) or typecheck fails on `@/global.css`; generate route types with `CI=1 npx expo start --offline` (09 §1).
> **Branches:** integration branch is **`mobile/develop`** (from `master`, goes to GitHub). Every card branches from
> `mobile/develop` and is merged back into it after review. **Nothing is merged into `master`** until the user decides.
