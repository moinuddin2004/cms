## Executive summary

**Critical: 0 · High: 4 · Medium: 13 · Low: 24**

The security core is in good shape. Staff and patient JWTs are separated by secret + `aud` + a fail-closed `PatientFenceGuard`; every patient query traced goes through `linkedPatientWhere` / `visibleScope` with the context rebuilt per request (a revoke is effective on the next call); claim, visit and login tokens are random, hashed, expiring and (claim/login) single-use under row locks/CAS; refresh rotation is a compare-and-swap with reuse detection; no SQL is built from user input; realtime rooms are derived server-side. All typecheck/lint/fence checks and all 2,070 unit tests that can run without a database pass.

The defects that matter are about **data lifecycle and patient safety rather than access control**:

1. A **forced** patient sign-out (remote session revoke, refresh-token reuse, `ACCOUNT_DISABLED`) does not cancel local medicine reminders — a lost phone keeps showing "Name: Medicine dose" on the lock screen for up to 72 h, defeating the "remote revoke" control in docs/03 §1.
2. Deleting a patient account / family member **keeps all medication schedules and dose history** (soft delete never triggers the `ON DELETE CASCADE`), contrary to A-22, docs/07 §6.6, the service's own comment, and the **published privacy policy**.
3. Medicine reminders are **only re-planned while the patient space is mounted**; a user who stays in the staff space (or doesn't open the app) for >72 h silently loses all reminders, and clinic-stopped schedules keep ringing.
4. The prescription **frequency parser turns non-daily wording into daily reminders** ("once in 3 days", "once a fortnight", a bare stat "once" → every day at 08:00, with no end date when no duration is given) — a direct over-dosing risk.

Fix those four before the patient pilot. The Medium items (forced staff sign-out cache leak on shared tablets, push templates editable to full names, revoke blocked when the clinic switches the app off, stale staff sockets, login-code/email abuse limits, privacy-policy retention claims without code) should be fixed or explicitly accepted before store submission.

## Verified OK

- **JWT separation:** patient secret required at boot and ≠ staff secret, HS256, `aud:'patient'`, 15 min; strategy re-checks live session + active account per request; staff tokens rejected on `/patient-api` and patient tokens on staff routes and `/realtime` (secret + `assertStaffAudience`). `PatientFenceGuard` first in the chain, fail-closed incl. case variants; identity on `request.patientAuth`, never `request.user`. `patient-api-coverage.spec.ts`, route-matrix, link-isolation, strategy specs exist.
- **Refresh rotation:** `<uuid>:<32 bytes>`, sha256 only, CAS on current hash (two parallel refreshes cannot both win), previous-token reuse revokes and emits a socket revocation; header (not cookie) → no CSRF.
- **Login codes:** `randomInt`, 6 digits, 10 min, peppered sha256, constant-time compare, atomic `attempts < 5` update, CAS on `used_at`, generic `CODE_INVALID`, `start` always `{sent:true}`, code never logged.
- **Google:** issuer + `email_verified === true`; patient match on `sub`, email fallback only when no other subject linked (else `ACCOUNT_LINK_CONFLICT`); staff never auto-links an account with a password or another Google link.
- **Patient isolation:** `PatientLinkGuard` rebuilds context per request from non-deleted profiles and `active`/`frozen` links; `linkedPatientWhere` always adds a predicate (`1 = 0` when none), unique param names; all reads via `visibleScope` (A-19); `:id` UUID-checked then scoped lookup → 404; explicit DTOs, explicit column lists, no entity spreading; diagnosis gated by `show_diagnosis`, billing by `show_billing`; only finalized/signed prescriptions; PDF `no-store`; `patient_access_log` on every clinical read; bounded limits everywhere.
- **Profiles / links / account delete:** every statement filters `account_id` + `deleted_at IS NULL`; self profile protected; delete blocked with live links; account delete removes identities, login codes, devices, revokes sessions (IP/device nulled), strips the account, revokes links with audit, drops sockets (gap: H2).
- **Staff link management:** `@Can` on all routes, org + patient scope on every query, approval/suspension/feature checks, patient row lock, older tokens invalidated, ids-only audit, masked email.
- **Claim tokens:** 32 random bytes base64url, sha256, 15 min, format check first, `SELECT … FOR UPDATE` single use, one `CLAIM_INVALID`, unique index + `ALREADY_LINKED`, rate limited. **Visit tokens:** 32 bytes, hashed, generic 404, rate limited; `/v/$token` no-referrer + noindex. Tokens masked in logged paths (`maskTokens`).
- **Rate limiting:** `RateLimiterGuard` is a global `APP_GUARD` before auth; every new public route has `@RateLimit`. (Production must set `TRUST_PROXY` correctly — see device/infra list.)
- **Patient realtime:** patient secret + `aud` + live session; account room from token; entry rooms only after a DB join through active/frozen links in approved clinics, re-checked on `links`; ≤5 sockets/account; closed on token expiry, logout, reuse, account deletion; id-only payloads; staff sockets cannot join `patient:*`.
- **Push text:** patient events (`queue.turn_near`, `queue.called`, `appointment.reminder`) carry clinic/doctor/time only; staff `queue.checked_in` push uses `{patient_first_name} · Token` (gap: M2 template override). Expo receipts prune `DeviceNotRegistered`.
- **Product events:** catalog names only, enumerated props, only account id stored — no PHI.
- **SQL injection:** every interpolation is a code constant; all user input bound.
- **Module registration:** every new controller is declared in a module; every new module reaches `AppModule` (`PatientDevicesModule`, `MedicationsModule` transitively via `PatientAppModule`/`NotificationsModule`/`QueueModule`); `@Interval` jobs only where `ScheduleModule` runs (see L19 for the startup sweep).
- **Medication sync / queue push:** sync idempotent via advisory lock + `uq_medication_schedules_profile_rx_medicine`; re-finalize updates in place and stops removed lines; patient edits kept; start = clinic-tz date of `signed_at`, end inclusive; A-23 paths as written. Patient queue pushes run in a `patient_push` savepoint inside the orchestrator tx; turn-near marker is a conditional UPDATE (sent once, replays skipped). Staff flows unchanged apart from extra reads. `expo-server-sdk` (ESM) loads under CommonJS on Node 22.
- **Demo seed (M4-03):** refuses in production unless an extra flag/env is given, requires a strong `DEMO_STAFF_PASSWORD` (no defaults/known seed passwords); not wired into app boot.
- **Mobile:** access tokens memory-only; refresh tokens in SecureStore `AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY` under the spec keys; per-space encrypted MMKV with random key in SecureStore, single-flight open, wipe deletes instance + key; persist allow-lists minimal (no search/list/check-phone; paused mutations never saved); prefs hold only space/language/flags/segment/theme; no `console.*` outside `core/log.ts`; A-24 scrubber; patient axios has no tenant-header path; separate clients/QueryClients/stores; single-flight refresh with generation guard; voluntary sign-outs complete and isolated per space; claim deep links validate 43-char base64url before any request and never echo; push taps are hints only (UUID-shaped, cross-org needs a switch prompt); realtime only invalidates (A-07); reminder planner uses phone wall-clock (DST-safe), inclusive start/end, `(now, now+72h]` cap 60, collision-free ids, only `active` schedules, private-reminder text per §5; dose queue newest-wins, single-flight, batch fallback; no `toLocale*String` on dates / `toISOString().slice`.
- **Fences:** grepped every import — no violations (lint gaps: L15).
